# 双源更新设计（2.2.7起；2.2.8补齐页面链接白名单）

## 用户交互

沿用版本弹窗、后台下载、取消、稍后安装、投屏结束确认和失败回滚。启动只检查版本，不测速、不下载。

| 用户情形 | 行为 |
| --- | --- |
| 国内直连、境外网络、开着系统代理 | GitHub/Gitee 并发检查；下载时比较直连和已配置代理的实际传输表现 |
| 一个通道超时、限流或服务器故障 | 使用另一个成功通道；不把整个检查判成失败 |
| 两个通道版本不一致 | 选择查到的最高稳定版本，只下载该版本，不以旧镜像冒充最新 |
| 最新版本尚未上传附件 | 显示该版本尚无可用更新包；不退回更旧的包 |
| 无新版或开发版高于公开版本 | 不下载、不测速、不降级；若只查通一个源，说明检查范围 |
| 点击下载 | 显示“正在选择下载源”，并发取最多512 KiB的ZIP头部；最多等待5秒，首个有效样本完成后再留1秒比较 |
| 源服务器不支持Range | 小段GET后关闭连接，仍可参加测速；完整下载允许从头重来 |
| 下载卡住、持续低速、连接断开 | 先切换另一个可用源/网络路径，再有限重试；弹窗显示当前来源 |
| 切换源、取消再继续、关应用再开 | 同源验证ETag续传；跨源只有同一SHA256和大小才续传，否则重新下载 |
| 所有源都很慢 | 不反复切换；仍可用的源继续下载，用户可取消 |
| 全部网络失败、磁盘不足、校验失败 | 结束任务并保留可安全续传的缓存；重试重新测速；写盘失败直接报错 |
| 下载期间发布了新版本 | 下载任务始终锁定已选择的tag，下一次检查再获取新版本 |
| 下载已完成 | 校验、暂存与安装不受在线源失效影响；沿用安装事务及回滚 |
| 打开网页 | 浏览器只允许两个正式仓库、latest发行页和固定稳定tag发行页；2.2.8修复2.2.7遗漏Gitee页面的旧白名单 |
| 仓库入口（2.2.9） | 两个等宽图标链接居中排列，GitHub外圈呈黑色、Gitee使用红色圆标；取消独立手动下载入口，保留悬停提示和键盘焦点 |

## 约束

- 只接受两个固定公开仓库的稳定Release与固定tag附件地址。Gitee自动生成的源码压缩包不作为更新包。
- 只允许HTTPS及已核对的GitHub/Gitee下载域名（包括foruda.gitee.com），每次请求固定原始Release URL，不保存会过期的CDN签名地址。
- 版本检查上限15秒，各源最多12秒。代理备用请求延迟750毫秒启动；已成功的请求不会等待失效代理。
- 测速计入连接、重定向和实际传输耗时。失败样本保留为后备候选，不能因一次测速超时永久禁用一个源。
- 下载连续12秒无数据自动切换；每10秒观察传输速度，下载至少20秒且剩余大于5 MiB时，发现备用源快两倍以上才切换。速度低于256 KiB/s且尚无已知快源时，额外并发测一次备用源（上限3秒），期间当前下载继续；未找到更快源则继续当前下载。各路径最多两次、总尝试最多八次，已经失败的路径不作为低速切换目标。
- API不可用但已通过latest重定向确认tag时，保留该tag，下载时探测两种规范附件名称；不因附件HEAD超时丢弃已发现版本。
- 判断换源是否更快时，计入连接开销及无法续传时的整包重下成本；预计至少节省25%的剩余时间才切换。接近完成时不会仅因另一个源测速更高而重下整包。
- GitHub提供的SHA256作为同版本包的共同校验值；如果只能访问Gitee且没有SHA256，则允许固定HTTPS来源下载，仍检查完整大小、ZIP CRC、必需文件与EXE版本。此时禁止跨源拼接续传。
- 系统代理和直连分别作为候选网络路径，测速及正式下载使用同一条路径。用户无需配置源、登录或提供令牌。
- 不绕过系统或工具的安全授权；本功能不需要在线写入权限。

## 发布约定

两个仓库同步上传同一个ZIP，tag、EXE版本与GUI版号同步。同步工具应校验SHA256；后续可同时发布校验文件供单源网络读取。当前公开v2.2.0原包EXE版本与tag不符，正常更新仍会拒绝安装，不更改这个保护。

## 本次范围

修改更新器、版本弹窗及版号并构建开发版；不创建公开Release，不推送未经用户验收的新提交。本次未要求运行测试，保留已有测试文件，使用编译和代码审查检查实现。
