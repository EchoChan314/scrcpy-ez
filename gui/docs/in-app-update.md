# 应用内更新交互与安装设计

## 用户流程

版本按钮打开现有版本弹窗。启动时只静默检查版本，发现新版保留红点，不自动下载或安装。

| 情形 | 界面与动作 |
| --- | --- |
| 检查中 | 显示检查状态，禁用下载，界面继续响应 |
| 已是最新/本地版本更高 | 显示准确状态，不自动重装或降级 |
| 有新版 | 显示版本，按钮“下载更新” |
| 下载中 | 显示进度、已下载量与速度，提供“取消下载” |
| 关闭弹窗 | 后台继续下载；重新打开显示同一任务 |
| 取消/网络失败 | 保留部分下载，按钮“继续下载/重试下载”；Range 不可用时重新下载 |
| 校验/解压中 | 显示正在准备，禁止安装，仍可关闭弹窗 |
| 下载完成 | 保留缓存，提供“稍后”与“重启并更新” |
| 存在投屏窗口 | 安装前在同一弹窗确认将结束窗口；取消确认不影响投屏 |
| 安装准备失败 | 留在旧程序内显示原因，不关闭应用 |
| 安装中 | 启动临时更新器，旧程序按既有退出链清理，然后替换并重开 |
| 替换失败 | 恢复已修改的文件并重开旧程序，保留可读结果 |
| 下载后退出/再开 | 恢复可安装的缓存；安装前重新验证文件 |
| 安装目录不可写 | 提示移至可写目录，可通过底部仓库图标查看发行信息 |

## 文件与版本规则

- 固定使用 GitHub / Gitee 公开 scrcpy-ez 稳定 Release，并发获取最高可见稳定版本。优先 API 获取附件大小与 SHA256，API 不可用时复用 releases/latest 的 HEAD 检查；详见 [双源更新设计](dual-source-update.md)。
- 固定版本下载地址，下载期间新 Release 不改变当前任务。HTTPS 重定向只允许已核对的 GitHub / Gitee 下载域名；不缓存会过期的 CDN 签名链接。
- 整包暂存并验证；限制下载和解压大小，拒绝越界路径、符号链接、重复文件与 Windows 特殊路径。
- 永不覆盖 profiles.json、settings.json、config.txt、日志、备份、缓存和本地更新结果。
- 普通更新只接受比当前版本更高的三段稳定版本；旧公开包只在隔离测试中使用模拟版本。
- 更新器从缓存中的自身副本运行，避免主程序自覆盖；等待旧进程退出，并在替换前重新校验暂存文件。
- 每个文件先备份再替换；安装失败恢复修改过的文件。新程序健康确认后才清理备份。
- 先将暂存文件完整写到安装目录内的临时文件并同步，再用 Windows MoveFileEx 原子替换；恢复也使用原子替换。备份记录 SHA256，恢复时校验，支持中断后再次恢复。
- 新版必须确认界面就绪及实际运行版号；替换后无法启动、启动退出或60秒未就绪会恢复旧版。下次启动发现遗留事务会启动独立更新器恢复。
- 安装结果写入本地结果文件，重开后的版本弹窗可显示结果。
- 更新不会自动推送 Git 或创建 Release。

## 验证范围

模拟 HTTP 验证进度、取消、Range、网络失败及哈希失败；构造 ZIP 验证保留档案、非法路径、必需文件；隔离目录验证事务回滚及真实公开包。真实软件目录仅部署本次开发版，不拿旧公开包覆盖用户使用目录。

## 发布要求与本次验证

- 新 Release 的 tag、GUI 内嵌版本与 EXE 文件版本必须同步；新增 UiReady 协议从2.2.6开始生效。
- 公开 v2.2.0 同名本地包内部文件版本为2.1.87。实际 GitHub 下载得到的前4.5MB与本地包一致；正常更新会拒绝这种版号不一致的包。
- 测试公开旧包使用隔离安装目录及包内实际版号，不提供产品内降级开关。2.2.6的正常安装、启动失败回滚、中断恢复，以及公开旧版启动均已在隔离目录执行；测试实例禁止访问真实 ADB。
- 本机公网下载三分钟只得到约4.5MB，完整公开包验证使用本地已有发行包。网络传输完整性、取消续传和重试另用可控 HTTP 服务验证。
- 常规全库测试与前端测试通过；更新模块及新增入口的 race 检查通过。全库 race 检查发现 DebugLog 发送与 DisableDebugLog 关闭 channel 的竞争，在已提交2.2.5的隔离副本中也复现；另有一次旧设备状态用例偶发失败。这两项作为既有测试问题记录。
